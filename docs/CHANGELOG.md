## 1.5.0 — 2026-10-24

这一版是「狗背上的方块」大更新：挂件系统从能挂、能开界面，做到能烧、能放歌、能跟着狗跑。

### 新增

**把方块挂到狗身上**
- 手持任意有方块形态的物品 **右键狗**：先挂左侧，左侧已占就挂右侧，两侧都占满则替换左侧；
  被替换下来的方块连同容器里的东西一并还给主人。
- 手持方块 **Shift + 右键狗**：挂到**你站的那一侧**（该侧已占但另一侧空着就用另一侧；
  两侧都满则替换这一侧）。以前这个操作会被「打开界面」抢走，导致左边有熔炉时右边挂不上。
- **Shift + 右键**（空手或手持非方块）：打开已挂方块的界面。
- **「取出狗身上的挂件」快捷键**：默认 **G**，可在「控制 → 人狗同行」里改键。
  主人按下后把 8 格内最近的狗身上两个挂件（连同容器内容）收回背包，背包满了掉在脚边。

**支持的方块界面**
- 工作台、熔炉 / 高炉 / 烟熏炉（真烧炼）
- 箱子 / 木桶 / 潜影盒 / 漏斗 / 发射器 / 投掷器 / 合成器（27 格容器，内容入档）
- **末影箱**（打开的是主人自己的末影箱库存）
- **酿造台**（5 格）、**讲台**、**信标**
- **切石机、砂轮、织布机、锻造台、铁砧、附魔台、制图台**

**炉子是真的会烧**
- 挂上去的那一刻容器就建好，之后每 tick 用原版 `AbstractFurnaceBlockEntity.serverTick` 驱动：
  燃料消耗、烧炼时长、配方查询、经验全部沿用原版。
- 打开的是原版 `FurnaceMenu`，火焰与进度箭头正常显示。
- 燃烧时挂件会换成 `LIT` 外观，并从狗的身侧持续冒火苗 / 烟，熄火后自动恢复。
- 虚拟炉子放在世界最低点以下，原版 `setBlockAndUpdate` 会被直接拒绝，绝不会真的在世界里放一个熔炉。

**唱片机 + 唱片**
- 狗身上挂着**唱片机**时，主人拿任意唱片 **Shift + 右键狗** 就会按原版播放这首歌
  （RECORDS 音源、音量 4.0，附近所有人都能听到），头顶冒音符粒子；唱片不消耗，可以反复听。
- 音乐由客户端自己持有 `SoundInstance`，**唱片机一被取下 / 替换 / 狗离开，音乐立刻停**。

**`/hd` 指令体系**（取代旧的 `/mode` 与「只允许一条命令」的限制）
- `/hd role <human|dog|spectator>`：仅开局前的等待阶段可用，目标身份已被占用则失败。
- `/hd age`：只有狗能用；重新走一遍「小狗 / 成年狗 → 狼变种」。
- `/hd swap`：需要 GAMEMASTER 权限；人和狗都在线时互换身份。
- 等待界面里可以直接按 **T** 打开聊天框输入 `/hd`，不必先退出等待界面。

**其他**
- 狗上岸甩水动画（原版狼的 shake），纯客户端驱动，不影响判定。
- 伙伴掉线时世界暂停并显示等待界面（新阶段 `WAITING_PARTNER`），回来即继续。

### 修复

**挂件渲染（这一版的主要战场）**
- **方块完全不显示**：26.3 的 `Display` 没有 `DATA_TRANSFORMATION_ID`，变换被拆成
  translation / leftRotation / scale / rightRotation 四个同步数据项，只有写它们才会把
  `updateRenderState` 置脏。原先 `set` 一个不存在的字段 → `renderState` 永远为 null →
  `DisplayRenderer.submit()` 第一行就返回。改为调用 `Display.setTransformation(...)`。
- **包围盒零尺寸被剔除**：`Display` 默认 `width/height = 0`，AABB 是一个点，
  EntityCulling 之类的优化 mod 会把它裁掉。现在设置了非零尺寸。
- **纯客户端实体不生成渲染状态**：`Display` 的 `renderState` 在它自己的 `tick()` 里生成，
  这里每帧手动推一次。
- **不跟着狗走**：渲染用 `Mth.lerp(partialTick, xOld, getX())`，
  而挂件的 `xOld` 停在创建时的 `(0,0,0)`。现在每帧把新旧坐标都对齐到"狗的位置 + 偏移"。
- **走路时抖动**：上一帧坐标改为「狗上一帧位置 + 上一帧朝向算出的偏移」，与狗完全同步插值。
- **不跟着狗转身**：朝向烘进 `setTransformation` 的 leftRotation（`Display` 的 yaw 通道对纯客户端实体不可靠），
  并改成朝向狗的**侧面**（左侧 -90°、右侧 +90°）；侧边位置改用 `yBodyRot` 计算，抬头低头不会把挂件拉进身体。
- **左侧太靠外**：方块模型以 `(0,0,0)~(1,1,1)` 为基准，直接旋转是绕"角"转、偏出半格。
  现在把水平中心平移到原点再旋转，两侧对称。
- **左右高度不一致 / 偏矮**：纵向改用**底边对齐**（半高模型如砂轮不会再比整方块矮一截），
  挂载高度抬到腰侧。
- **切换方块不换外观**：只在方块 id 变化时调 `setBlockState`，不再每帧重置。
- **重新进入世界后不显示**：之前只在 JOIN 那一 tick 发一次同步包，客户端没就绪就丢。
  现在每 20 tick 全量重发一次挂件数据，重连 / 丢包都能自愈。

**熔炉 / 菜单**
- **熔炉界面打开后瞬间关闭**：`AbstractFurnaceMenu.stillValid` 会走
  `BaseContainerBlockEntity.stillValid`，要求"玩家离方块 4 格内且该坐标仍是这个方块实体"，
  虚拟炉子两条都不成立。现在虚拟炉子覆盖 `stillValid` 恒为 true。

**狗本体与交互**
- **F3+B 显示碰撞箱后，狗穿不过一格高的空间**：尺寸缓存可能停在 1.8 高。
  现在服务端每 tick 比对实际碰撞箱与期望尺寸（成年 0.6×0.85 / 幼犬 0.3×0.425），
  不符立即 `refreshDimensions()`。
- **可以打狗**：左键命中替身狼时把攻击目标换成狗玩家本体（`@ModifyVariable` 改写
  `MultiPlayerGameMode.attack` 的参数），伤害走原版流程，会正常触发死亡联动倒计时。
- **真正的碰撞箱、可被挤压**：记分板队伍的碰撞规则从 `NEVER` 改回 `ALWAYS`
  （`NEVER` 会让「谁都推不动它」），并删掉只取消人↔狗互推的两个 mixin。
- **狼铠挡住宿主的第一人称视野**：`WolfArmorLayer` 不检查隐形标志，替身狼被隐藏时护甲照样提交。
  现在隐藏替身狼时同时清空 BODY 装备槽。
- **剪刀取不下狼铠**：新增分支——手持剪刀右键穿铠的狗即取下，狼铠回到主人背包（满了掉落）、
  撤销护甲加成、剪刀 -1 耐久、播放 `WOLF_ARMOR_CRACK`。
- **狼铠不生效**：护甲加成（+11）是瞬时属性修饰符，会被同步覆盖，现在每 tick 重新施加。
- **狗本体改用「渲染层」隐藏**：之前用 `isInvisible()` 藏狗本体，会让 Jade 这类信息 mod 直接跳过它
  （看不到血量与效果）。现在实体保持可见，只在 `LivingEntityRenderer.extractRenderState` 里把
  两个可见性标志设成「完全不可见」；本体头顶多余的名牌也单独隐藏。
- **坐下真正坐得住**：服务端虽然会把坐下狗的移动包钳回原地，但客户端仍按自己的位置预测一路走出去。
  现在直接在客户端 `ClientInput.getMoveVector()` 里清零输入。

**视角与指令**
- **F6 → F5**：去掉 F6 自定义低视角切换，改用原版 F5 循环第一人称 / 第三人称背面 / 第三人称正面。
- **第一人称视角**：狗在第一人称显示手（含 F5 循环进来的第一人称）；只在第三人称隐藏手。
  相机高度跟随狼眼高度（成年 0.68 / 幼犬 0.34375）。
- **解除「只允许一条命令」的限制**：删除 `CommandsMixin`（曾让除 `/mode` 外的命令都不执行）
  与 `ModeCommand`，删除 `MinecraftMixin`（禁用 F3+F4）与 `KeyboardHandlerMixin`（F6 / 拦截 F3+N），
  改用标准 `/hd`。

## 1. 项目现状

| 维度 | 现状 |
|---|---|
| 平台 | Minecraft 26.3 / Fabric Loader 0.19.5+ / Fabric API / Java 25 |
| 入口 | `HumanAndDogMod`（服务端）+ `HumanAndDogClient`（客户端） |
| 状态管理 | `GameSession`（每存档一份，`GameSessions` 单例）＋ `GamePhase` 四态状态机 |
| 网络 | 6 个 `CustomPacketPayload`：阶段、狗外观、身份状态、开角色界面、开变种界面、选择回包 ×2 |
| 存档 | `ModSaveData`（`SavedDataType`，Codec 序列化到主世界 `data/human-and-dog/game_data.dat`） |
| 客户端渲染 | 替身狼 `DummyWolf`（纯客户端实体）＋ `DogClientManager` 每 tick 同步 |
| 注入点 | 服务端 7 个 mixin、客户端 10 个 mixin |

**设计核心**：狗的"身体"始终是一个普通的 `ServerPlayer`（共享原版玩家碰撞、伤害、维度逻辑），
只在客户端用一只替身狼盖住它。所有玩法（拴绳、死亡联动、跨维度）都作用在玩家实体上，
渲染层是可替换的皮。这个取舍让绝大部分原版机制"免费"可用，代价是**视觉与逻辑坐标系必须手动对齐**——
第 4 节的坑基本都来自这里。

## 3. 这轮改动的两个关键决策

1. **为什么既要客户端钳制又要服务端钳制。**
   玩家位置是"客户端权威"的：服务端对移动包做钳制后只是把自己的记录按住，客户端并不知情。
   掉崖时如果只做服务端钳制，客户端会一路坠到谷底，出现"服务端 15 格、客户端在深渊"的错位；
   如果改成每 tick 服务端 teleport 纠正，又会触发连续位置包导致抖动/惯性清零。
   最终方案：客户端把位移投影到球面上（平滑、无网络往返），服务端只做越过 15.05 格时的兜底拉回（防作弊/防传送跳变）。

2. **为什么阈值效果按"移动方向"而不是"距离"施加。**
   需求是"追不上、但回得来"。如果只按距离加缓慢，往回走同样被拖慢，玩家体验是"被粘住"。
   改成用本 tick 水平位移与"指向对方"单位向量的点积判定：点积 <0 判为远离 → 缓慢，>0 判为靠近 → 加速。
   站立不动与绕圈不吃任何效果（点积≈0），效果每 30 tick 刷新一次。

## 4. 历史 bug 归档（根因复盘点）

| 症状 | 根因 | 修复方式 |
|---|---|---|
| 狗重进后一直"等待玩家加入" | 等待阶段世界被强制暂停 → `MinecraftServer.tickServer` 不执行 → `END_SERVER_TICK` 不触发，状态机停在 `WAITING_DOGS` 无人推进 | `tickAlways()` 由 `IntegratedServerMixin` 在 `tickServer` 头部直接驱动；`recheckStart` 改成幂等 + 只在状态变化时广播 |
| 狗身上叠着"半透明人影" | 人狗同队 + 队伍默认 `seeFriendlyInvisibles = true` → 原版 `Entity.isInvisibleTo` 对队友失效 → 隐形玩家被半透明材质渲染 | `ensureNoCollisionTeam()` 里 `setSeeFriendlyInvisibles(false)`（存档里旧队伍也会被每 tick 纠正） |
| 狗走路没有动画 | 替身狼的坐标是"搬运"来的，原版 `aiStep → calculateEntityAnimation` 执行时位移恒为 0 | `DummyWolf` 屏蔽原版调用，改由 `DogClientManager` 用玩家的真实位移驱动 |
| 狗打生物偏移 / 打不到 | 眼睛仍在 1.62（人眼），相机/准星/命中射线都以它为原点，而狼只有 0.85 高 | 新增 `DogEyeHeightMixin` 把无参 `getEyeHeight()` 改成 0.68；**只改 getter 不动缓存字段**，避免浅水溺水回归 |
| 跨维度后狗彻底隐身 | 维度切换会整体替换 `ClientLevel`，旧替身狼挂在旧 level 上不会再被渲染 | `DogClientManager` 检测 level 变化整批重建；`discard()` 按"狼自己所属的 level"删除 |
| 房主选不了"当人" | 等待阶段同步会把角色界面保留住（我上一轮加的"保护"过度生效） | 点击后立刻切到等待界面 + 服务端拒绝改选，杜绝"同一人既人又狗" |
| 单人凑齐双方直接开局 | 同一玩家先选人再选狗，`human()` 与 `dogIds` 同时成立 | `selectRole` 拒绝改选；`assignDog` 里发现自己是房主就放弃房主身份 |

**共同教训**：所有"视觉替身 + 逻辑实体"分离的方案，必须把
**相机原点、拾取射线原点、渲染插值旧坐标、动画位移、隐形判定**这五件事逐一对齐；
只对齐其中一半就会以"偏移/打不到/抖动/隐身"的形式暴露出来。建议后续加改动时按这张清单过一遍。

## 5. 风险与技术债

**高优先级**

1. **专用服务器没有"暂停"语义。** 等待阶段的暂停依赖 `IntegratedServer.tickServer` 里的重定向；
   专用服务器上世界照常走时间、刷怪。多人服务器首局需要重新设计（例如等待期用 `tickRateManager` 冻结）。
2. **观战者不可转回参与者。** 名额一旦被占满，后来者只能观战；人/狗掉线后名额也不会自动释放。
3. **没有配置文件。** 12/15 格、40 血、4 点伤害、3 秒倒计时全部硬编码在常量里。

**中优先级**

4. 狗仍是 `1.8` 高的玩家碰撞箱：能撞头、能卡门框，但视觉只有 0.85 高。
5. 拴绳是"位置约束"而非物理绳：没有绳索模型、没有拉力音效，视觉上只是"停住/被拉"。
6. 语言只有 `zh_cn` / `en_us`；`zh_tw`、`ja_jp`、`ru_ru` 等需要社区补。
7. `CommandsMixin` 把所有非 `/mode` 命令全部吞掉，包括 `/help`；在专用服务器上对其他插件不友好。
8. 存档没有版本迁移层：`ModSaveData.CODEC` 只靠 `optionalFieldOf` 默认值兜底，字段语义变化（如 `role` 新增 `SPECTATOR`）靠 `Role.valueOf` 的 try/catch。

**低优先级**

9. 客户端预测与服务的钳制阈值相差 0.05 格，极端网络下可能有一帧看不见的抖动。
10. F6 视角切换与"眼高恒为狼眼"叠加后，第三人称视角比人类低很多（设计如此，但老玩家会觉得变了）。

## 6. 手动验收清单（每次发版前跑一遍）

1. 新建世界 → 选「当人」→ 出现等待界面、太阳不移动；
2. 对局域网开放 → 第二客户端进入 → 看到角色界面且「当人」置灰 → 选「当狗」→ 选变种 → 双方自动开局；
3. 聊天框出现「欢迎游玩！！！」；
4. 第三客户端进入 → 自动观战（旁观模式），人在人狗附近；
5. 人狗相距 >12 格：远离方变慢、靠近方变快；<12 格恢复；
6. 狗从悬崖跳下 → 停在 15 格处悬空，不掉血；
7. 任一方式死亡 → 双方定格 + 3 秒倒计时 + 共享重生点复活；
8. 人/狗进下界 → 双方同时过去，狗仍能看见狼、不再是透明人影；
9. 狗打牛/僵尸/鸡：命中位置与准星一致；
10. F6 切第一/第三人称，手部与视角正常。

## 7. 下一步建议

- **配置化**：把拴绳距离、血量、伤害、倒计时做成 `config/human-and-dog.json`（Fabric 的 `fabric-loader` 配置 API 或自研 GSON）。
- **名额回收**：参与者离线超过 N 分钟释放名额，观战者可晋升（需要一次身份变更协议）。
- **专用服务器适配**：等待期冻结时间（`TickRateManager` / `gameRules.randomTickSpeed 0`）并给出提示。
